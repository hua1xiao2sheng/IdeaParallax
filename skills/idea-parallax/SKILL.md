# IdeaParallax

This skill belongs to a standalone project. Do not edit another project or import its
workflow as a new dependency. Find this repository and read README.md and docs/ADAPTERS.md.

1. Preserve the user's raw research scope, constraints, preferred language and supplied
   papers in a new brief JSON. Do not narrow the question to the host's favorite idea.
2. Run `python -m idea_parallax doctor`. Do not read, copy or request authentication files.
3. Read the chosen branch configuration. Explain whether each branch is a strategy port,
   imported instructions, native-Codex attempt or external adapter. Never conflate these.
4. For a normal Codex/API run, use a new output directory and the `run` command in README.
   Let the program handle parallelism, isolation, durable states and blind review.
5. No unrequested network retrieval, upstream trust, external code execution, full training,
   GitHub publication or contact with students. Native/command mode needs explicit permission.
6. Read report.json plus report.md. Report branch failures and unknown evidence, not merely
   the number of generated candidates. A success status means a valid response, not that
   an upstream research workflow or experiment has been independently verified.
7. Return distinct candidate families with their source modes, mechanisms, closest registered
   evidence, falsification plan, costs/unknowns and next action. Ask the researcher to choose
   which direction to explore; do not pretend model agreement guarantees publication.
8. Resume only with unchanged fingerprints. Never silently change a model, increase the
   budget, substitute a different project or fall back to synthetic demo data.

A user explicitly requesting a demonstration may use `demo`. Its deterministic fixtures
must remain marked SYNTHETIC DEMO in every explanation and report.
